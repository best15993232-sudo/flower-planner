# 검색 노출 개선 계획 2.1판 (언제 졸업해? · 오늘의 양재 꽃시세)

- 1판: 2026-11-20 / 2판: 2026-11-20 (GPT 검토 + 직접 확인) / **2.1판: 2026-11-20** (학교 바로가기 C안 확정, 연간 원자료 형식 확인) · 11/20 보충: 새 페이지에 위치 경로 구조화 데이터
- 대상: `flower-planner`(언제 졸업해?), `flower-sise`(오늘의 양재 꽃시세)
- 순서: **언제 졸업해? 먼저** (졸업식 검색은 12~2월에 몰리고, 네이버 반영에 몇 주 걸림). 꽃시세는 그다음.

## 0. 한 줄 원칙

검색용 페이지 수를 늘리는 것보다 **처음부터 읽히는 글자 페이지 + 그 페이지에서 끝나는 답 + 정확한 기준일·출처 + 실패해도 안전한 자동 갱신**을 먼저 검증한다.

## 2. 확인된 사실 (2026-11-20, 코드·데이터·관리 화면 직접 확인)

**공통**
- 두 사이트 모두 목록·시세를 페이지를 연 뒤 채우는 방식이라, 검색 로봇이 처음 받는 글자에는 학교명·꽃명·가격이 거의 없다.
- robots.txt는 두 사이트만 허용(맨 위 주소 저장소에서 관리). 네이버 robots 검사 "수집 가능", 다음 로봇룰 "수집·색인 가능".
- 사이트맵: 각 사이트 `sitemap.xml`(메인·개인정보 페이지만). 네이버·구글 11/9 제출, 다음 11/16 제출.
- 구글: 두 사이트 모두 색인됨(플래너 11/10, 꽃시세 11/16 크롤링). 다음: 두 사이트 모두 검색됨.
- **네이버: 두 사이트 모두 아직 수집 전**("URL 검사 결과 없음"). 맨 위 안내 페이지만 수집됐는데, 그때는 검색 제외(noindex)였음. 11/20에 제외를 풀고 사이트 이름 정보를 넣음 → 다 바꾼 뒤 다시 수집 요청.

**언제 졸업해?**
- 졸업식 일정은 학년도가 아니라 **날짜 범위(2026.12.1~2027.2.28)**로 나이스에서 가져온다 → 2026학년도 누락 위험 없음.
- 학교 공지 보정 날짜는 별도 파일(`data/school_notices.json`)에 출처·확인일과 함께 있고, 매일 갱신 때 우선 적용된다.
- 대학 학위수여식 296곳은 모두 학교 공식 페이지 원문으로 확인한 것만 들어 있다.
- 졸업생 수 = 학교알리미 2026년 공시(4월 기준)의 최종 학년 재학생 수.
- 매일 새벽 `update-data` 작업이 데이터를 만들고 main 브랜치에 저장 → GitHub Pages가 그대로 배포.
- 메인에는 주소로 특정 학교를 여는 기능이 없다(`?demo=1` 체험 모드만 있음).
- **주소 글자로 지역을 나누면 틀린다**: 세종시(구 없음)·시 이름이 빠진 주소 때문에 엉터리 묶음 311개가 나옴.

**꽃시세**
- `snapshot.yml`이 **15분~1시간마다** 시세 서버에서 `data/snapshot.json`을 받아 바뀌었으면 저장한다.
- 시세 서버(구글 시트)는 최근 8주 추이 원자료만 계산에 쓴다. `snapshot.json`의 `rows` 1,429개는 품목·품종별 8주 흐름.
- **1년치 과거 원자료가 있다**(사장님 보관분). 시세 서버 스프레드시트 `연간집계_원자료` 탭에 붙여 넣는 중.
  - 형식(11/20 확인): `경매일, 품목, 거래량(속), 거래금액(원), 품종 수` → **품목 단위 하루 합계**. 품종·등급 없음. 평균가 = 거래금액 ÷ 거래량.
  - 11/20 확인 시 **1,000줄(2025-10-31~2025-11-12)만** 들어 있음 → 나머지를 사장님이 이어 붙인 뒤 시작·끝 날짜와 빠진 경매일을 확인해야 함.
- `sw.js`는 아무것도 저장하지 않고 항상 새로 받는다 → 홈 화면 앱의 옛 화면 문제 없음.
- aT 오픈API 활용 기간: 2028-07-06 무렵 만료.

## 5. 언제 졸업해? 계획

### 5-1. 지역 나누기 (먼저 할 일)
- 이미 쓰는 카카오 주소 변환(`scripts/fetch_dongs.py`)에서 **시·군·구 이름과 행정구역 코드**를 같이 받아 저장한다.
- 구가 있는 시(수원·성남·고양 등)는 구 단위, 세종·제주는 예외 규칙.
- 주소는 이 코드로 만든다: `/flower-planner/area/41135.html`

### 5-2. 페이지
| 페이지 | 주소 예 | 내용 |
|---|---|---|
| 전국 요약 | `/flower-planner/area/` | 월별·학교급별 학교 수, 확인된 날짜 기준 가장 많은 날, 시·도 링크 |
| 시·도 | `/flower-planner/area/41.html` | 시·군·구별 학교 수·가장 많은 날, 시·군·구 링크 |
| 시·군·구 | `/flower-planner/area/41135.html` | 학교급별 표(학교, 졸업식 날짜·요일, 졸업생), 날짜별 학교 수, **전체 / 날짜 확인 / 미정** 구분, 그 지역 대학 학위수여식 |
| Q&A | `/flower-planner/qna.html` | 날짜 출처(나이스·학교 공지), "졸업생 수는 최종 학년 재학생(2026 공시)", 날짜가 바뀌는 경우, 판매 장소 안내 |

- 모든 페이지: 로고(→메인), "우리 가게 주변 학교로 보기 →" 버튼(→메인), 상위·같은 시도 다른 지역 링크, 출처·"학교 사정으로 바뀔 수 있어요" 안내.
- 모든 새 페이지: 화면 위쪽 경로 링크(전국 › 경기도 › 성남시 분당구)와 같은 내용의 **위치 경로 구조화 데이터**(JSON-LD BreadcrumbList). 페이지 만드는 스크립트가 같이 만든다. 검색 결과에 경로로 보일 수 있으나 보장은 없음.
- "가장 많은 날"은 **날짜가 확인된 학교만** 센 값이라고 표시.
- 학교 공지로 고친 날짜는 "학교 공지 확인"으로 표시.
- 발행 기준: 날짜 확인 학교가 **5곳 이상**인 시·군·구만 따로 발행 (2026-11-20 사장님 결정. 분포 확인 결과 256곳 전부 해당). 기준 미만은 시·도 페이지 안에 표로 포함하고 범위를 명시.

| 학교급 | 초등학교 졸업식 날짜, 고등학교 졸업식 2027, 대학교 학위수여식 일정 | 전국·시도 소제목 |

### 5-4. 지역 페이지에서 학교 이름을 눌렀을 때 (C안 확정)
| 방법 | 장점 | 단점 |
|---|---|---|
| A. 링크 없음 | 단순, 메인 변경 없음 | 담고 싶은 사람은 메인에서 학교를 다시 찾아야 함 |
| B. 학교 홈페이지로 | 메인 변경 없음 | 우리 사이트를 떠남(이탈) |
| **C. 메인의 그 학교 상세가 바로 열림 (확정)** | 바로 담기·지도·길찾기, 우리 사이트 안에 머묾 | 메인에 '주소로 학교 열기' 기능 추가 필요(화면 모양은 그대로) |
→ **C안 확정 (2026-11-20 사장님 결정)**. 메인에 '주소로 학교 열기' 기능을 더한다.
- 주소 예: `/flower-planner/?s=<학교 id>` (id는 `places.json`의 id, 주소용으로 인코딩)
- 열리면 지금과 똑같은 학교 상세 창. 메인 화면 모양·다른 동작은 그대로.
- 없는 id·오래된 id면 조용히 메인 기본 화면(오류 창 없음).
- 상세 창을 닫으면 주소에서 `?s=`를 지워서 새로 고침 때 다시 열리지 않게.
- 메인 방문 통계·개인정보에는 변화 없음(학교 id만 주소에 붙음).

### 5-5. 만드는 방법
- `update-data` 작업 마지막에 페이지 만드는 스크립트를 돌린다.
- 생성 → 검사(학교 수가 갑자기 크게 줄면 멈춤, 빈 페이지 금지) → 통과 시에만 저장.
- 정렬·숫자 표기를 고정해서 같은 자료면 같은 파일이 나오게 한다 → 바뀐 페이지만 저장.
- 페이지 안 "마지막 변경일"과 사이트맵 lastmod는 **그 페이지의 날짜·학교가 실제로 바뀐 날**만 바꾼다. 매일 확인일은 넣지 않는다.

## 6. 꽃시세 계획

### 6-1. 메인에 오늘 시세 미리 넣기
- **경매일이 바뀌었을 때만**(15분마다가 아니라) 메인 HTML 안 표를 다시 써 넣는다. 그 밖에는 지금처럼 `snapshot.json`만 갱신.
- 미리 넣는 표는 지금 화면과 같은 모양·순서. 화면이 열린 뒤 바뀌는 숫자가 없게 테스트.
- '오늘'은 그날 경매가 있을 때만. 없으면 "최근 경매일 11/18(수)".

### 6-2. 꽃별 페이지 (메인과 답하는 질문이 다르게)
| | 메인 펼침 칸 | 꽃별 페이지 |
|---|---|---|
| 질문 | 오늘 얼마? 지난주보다 올랐나? | 품종·등급 중 뭘 고를까? (자료가 되면) 1년 동안 어땠나? |
| 바로 가능 | | 품종별·등급별 비교(최소 거래 기준 적용), 거래량, 최신 경매일, 경매 단위·출처 |
| 연간 원자료 확인 후 | | **품목 단위** 1년 평균가·거래량 흐름, 연중 최고·최저 시기(1년 관측 사실로만), 작년 같은 기간 비교(조건 충족 시). 품종·등급은 8주 범위만 |
| 보류 | | 계절 달력, 요일 비교, 산지·보관 팁 (4절) |

- 발행 기준: 최근 거래 표본이 충분한 품목만. 나머지는 "기타 품목" 한 페이지.
- 꽃 이름 두 표기: 리시안셔스(리시안사스), 안개꽃(안개), 튤립(튜립), 알스트로메리아(알스트메리아).
- 모든 페이지: "경매 낙찰가예요. 소매가·도매상 판매가와 달라요." + 출처 + 경매일.
- 거래 없음은 '0원'이 아니라 "거래 없음".

### 6-3. 과거 자료 쌓기 (중복 없이)
- **경매일 × 품목 × 품종 × 등급** 단위 원자료를 쌓고, 주간·월간 값은 거기서 계산한다. 주간 평균을 매일 덮어 쌓지 않는다.
- 필드: 경매일, 품목, 품종, 등급, 거래 단위, 거래량, 평균·최고·최저가, 시장, 수집 시각.
- 저장 장소: 시세 서버 시트(새 탭) 또는 저장소 `data/history/` 월별 파일. `연간집계_원자료` 형식을 보고 정함.

### 6-4. 노리는 검색어
| 묶음 | 예 | 어디에 |
|---|---|---|
| 큰 말 | 꽃 시세, 화훼 경매 시세, 꽃 경매 시세, 절화 경매가, 양재 꽃시장 시세, 꽃 도매가 | 메인 제목·설명 |
| 꽃 이름 | 장미 시세, 안개꽃 가격, 카네이션 도매가 | 꽃별 페이지 |
| 품종 | 하젤 장미, 프리덤 장미 시세 | 꽃별 페이지 품종 표 |
| 행사·주간 | 어버이날 카네이션 시세, 이번 주 꽃값 | 행사·주간 페이지 (4단계) |

## 7. 실패해도 안전하게 (두 사이트 공통)

| 위험 | 기준 |
|---|---|
| 자료 받기 실패·일부 누락 | 이전 정상 페이지 유지, 0건을 실제 0으로 착각하지 않음, 실패 기록 |
| 만드는 도중 배포 | 생성 → 검사 → 통과 시에만 한 번에 저장 |
| 날짜만 바뀌는 파일 | 생성 시각을 본문에 넣지 않음, lastmod는 실질 변경일 |
| 기준일 오인 | 시스템 날짜가 아니라 실제 경매일·확인일 표기 |
| 빈약한 페이지 | 발행 기준 미달은 상위 페이지에 포함 |
| 이름 변경 | 코드 기반 주소로 고정 |

## 8. 단계별 진행과 합격 기준

| 단계 | 언제 졸업해? | 꽃시세 | 넘어갈 조건 |
|---|---|---|---|
| 0 | 행정구역 코드 받기, 지역 분포 계산 | `연간집계_원자료` 형식 확인 | 분포·자료 범위 파악 |
| 1 시안 | 전국 + 경기도 + 성남시 분당구 + Q&A + 학교 바로가기(C안) | 메인 표 미리 넣기 + 장미 1페이지 | JS 없이 핵심 글자 보임, 메인 그대로 |
| 2 검증 | 날짜·공지 보정·미정 구분 | 단위·경매일·표본 수 | 원자료와 일치, 휴대폰 화면 정상 |
| 3 확대 | 기준 통과 지역 전체 + 사이트맵 | 기준 통과 품목 전체 + 사이트맵 | 404·중복·빈약 페이지 없음 |
| 4 추가 | (두 사이트 연결은 하지 않기로 함) | 주간·행사 페이지, Q&A, 과거 자료 쌓기(11/20 자동 쌓기 시작) | 근거 충분 |
| 5 운영 | 색인·유입 관찰 | 같음 | 실제 검색어 기반 보강 |

기간은 목표 순서일 뿐이고, 검색 반영 시점은 보장할 수 없다.

## 9. 발행 전 체크리스트
- [ ] JS 없이 HTML 원문에 학교명·날짜 / 꽃명·가격이 글자로 있다
- [ ] 직접 접속 200, 휴대폰 화면 정상
- [ ] noindex 없음, canonical 맞음, 사이트맵 주소 = 실제 주소
- [ ] 제목·설명·본문이 그 검색 질문에 스스로 답한다
- [ ] 단순 치환·빈약 페이지 제외 규칙이 동작한다
- [ ] 모든 링크(상위·하위·관련·메인) 정상
- [ ] 자료가 같으면 다시 돌려도 파일·lastmod가 안 바뀐다
- [ ] 자료 받기 실패 시 기존 페이지가 사라지지 않는다
- [ ] 구조화 데이터가 화면의 경로와 같고 오류가 없다(구글 리치 결과 테스트)
- [ ] (플래너) 확인·미정·전체 구분, 공지 보정 유지, 대학은 공식 확인분만
- [ ] (꽃시세) 가격·단위·경매일이 원자료와 일치, 8주만 있을 때 1년 수치 안 만듦, 거래 없음·휴장일 표기

- 8~12주 뒤: "분당 졸업식 날짜", "장미 시세" 같은 일반 검색어의 노출·유입 평가.

## 11. 남겨 둔 문제
- **네이버와 github.io 주소**: 네이버는 여러 사람이 같이 쓰는 주소를 믿음 점수 낮게 시작한다. 지금은 주소를 유지하기로 했으므로, 몇 달 뒤에도 네이버만 유독 안 오르면 그때 자체 도메인을 다시 따진다(이 경우 이용자 일정 옮기기 방법도 같이 준비).

## 12. 다 바꾼 뒤 검색엔진에 다시 알리기 (사장님)
새 페이지를 올리고 검사가 끝난 뒤 한 번에 한다.
- 구글 서치 콘솔: 사이트맵 2개 다시 제출, URL 검사 → 색인 생성 요청(메인·전국 요약·맨 위 주소)
- 네이버 서치어드바이저: 사이트맵 다시 제출, 웹 페이지 수집(메인·전국 요약·시·도 몇 개·맨 위 주소)
- 다음 웹마스터도구: 수집요청 문서등록(같은 주소들), 사이트맵 Seed 다시 등록
